# 2 — Backlog 夜班：每晚唯讀跑一次，早上給一份短報告

狀態：只規劃，未實作，也還沒試跑過（2026-11-18）。

## 要解決的問題

使用者的原話：「就算我有一個管理 backlog 的看板, 但我也沒有辦法讓他自己被agent 處裡」。

看板只能顯示待辦，不能讓待辦被處理。待辦沒辦法自己被處理，原因有三個：

- 大部分項目在等人。thec-ops 的 backlog 在 2026-11-18 有 60 條，其中「等回饋或觸發」26 條、「正式庫要重新指派」9 條，共 35 條明寫著在等人。
- 項目沒有寫驗收條件，agent 不知道做到哪裡算完成。
- 家規規定所有程式碼變更都要使用者確認，agent 不能自己改。

所以第一步不讓 agent 動手做，只讓它先把「做決定之前的準備」做完。

## 做法

一張要使用者決定的單有五步：讀背景、查現況、整理選項、做決定、動手做。現在五步都是使用者自己來。夜班把前三步在前一晚做完，使用者早上只做第四步。

夜班每晚做三件事：

| 工作 | 做什麼 | thec-ops 今天的例子 |
|---|---|---|
| 審還沒審的 commit | 以審查員模式讀 diff，列出問題 | `d15e2e3`、`b0bd242`、`03ed5d9` |
| 巡「等別人」的項目 | 查對方該交的檔案或資料到了沒 | 採購對照表填了沒 |
| 準備決定 | 讀背景、查現況，整理成最多兩個選項 | 採購規格缺口 4 項 |

早報每項最多三行：結論、對使用者的影響、要使用者決定的事。沒有新進展的項目不寫。

## 邊界

- 夜班只讀。唯一能寫的是早報那一個檔。
- 不改程式碼、不 commit、不改 backlog、不改 `Memory.md`、不連正式庫、不發訊息。
- 早報放在專案的 `.claude/` 底下，不進版控。
- 每次執行有花費上限。

## 怎麼跑

- 用 `claude -p` 無人值守執行。
- `--allowedTools` 只開讀檔、搜尋、唯讀的 git 指令，加上寫早報那一個檔。
- `--max-budget-usd` 設花費上限。
- 排程用這台電腦的本機排程（傾向），不用雲端排程。理由是專案和資料都在本機。

## 檔案樹（暫定）

```
dotclaude/
├── night/
│   ├── night-shift.sh      新：對指定專案跑一次夜班（組指令、設權限與上限）
│   └── PROMPT.md           新：夜班的指令（三件事、早報格式、邊界）
└── tests/night-shift.test.sh  新：確認組出來的指令沒有開寫入權限

<專案>/.claude/night-report.md  夜班的輸出，加進 .gitignore
```

排程本身（本機排程設定）放哪裡，動工前再定。

## 試一週

- 範圍：只有 thec-ops。
- 成功：7 天裡至少 4 天，使用者照早報處理了至少 1 項。
- 失敗：連續 3 天沒打開早報。
- 立刻停：夜班寫了早報以外的任何東西。

## 之後的三級

每一級要前一級證明有用才做。

1. 唯讀夜班（本文件）。
2. 夜班在隔離分支上改小項，使用者早上看 diff 決定要不要合併。這就是 `1-herdr-dispatch.md` 的實作者模式，需要先改家規。
3. 看板。到這一步才有東西值得顯示。

## 不做的事

- 不裝 Paperclip。試用過（v2026.1106.0），功能遠超過一個人需要的，而且它自己也不會讓待辦被處理。
- 不先做看板。
- 不把 Codex 接進 `/r-review`（2026-11-17 使用者決定）。

## 風險點

- 早報沒人看。對策是試一週的失敗條件。
- 早報內容不準，使用者照著做錯決定。對策是每項附依據（檔案與行號、commit），查不到就寫「沒查到」。
- 權限設定擋不住寫入。對策是動工前先實測（見下）。
- 花費。每晚一次、有上限，但實際金額還沒量過。

## 動工前要再確認

- `--allowedTools` 實際擋不擋得住寫入和有副作用的指令。還沒實測。
- `claude -p` 底下 hook 會不會照常跑（SessionStart 注入、Stop 的語言檢查）。還沒實測。
- 花費上限設多少。先手動跑一次量實際金額再定。
- thec-ops 的 `.claude/` 有部分檔案進版控（`Memory.md`、`open-todo-backlog.md`），早報要另外加進 `.gitignore`。
- 「等別人」的項目要怎麼讓夜班知道去哪裡查。可能要在 backlog 項目上補一行「看哪個檔」。
- tx-trader 適不適用，還沒看。
