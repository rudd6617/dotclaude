# `.out-of-scope/`

本目錄記錄**明確決定不做的事**——以及不做的理由。

## 與 ADR、lessons 的差別

| 文件 | 用途 |
|---|---|
| `docs/adr/` | 「為什麼選 X 而非 Y」——做了的決策 |
| `.out-of-scope/` | 「為什麼不做 X」——拒絕的提議 |
| `.claude/lessons/` | 重複出現的失敗模式 |

`.out-of-scope/` 防止同一個提議反覆冒出來。Agent / 協作者讀過後，會知道某個方向已被深思熟慮地拒絕，不要再建議。

## 格式

每個檔案一個議題，命名為 `kebab-case.md`：

```markdown
# <一句話標題，敘述「不做什麼」>

<開頭一段：明確宣告不做的範圍>

## Why this is out of scope

<理由——含 trade-off、替代方案、邊界判斷>

## Prior requests

- <issue # / PR # / 對話日期> — <當時的提議>
```

## 何時新增條目

當你拒絕一個提議，**且**：

1. 該提議**可能再被提出**（不是一次性疑問）
2. 拒絕理由**不是顯而易見**（需要解釋）
3. 不適合寫成 ADR（ADR 是「做了什麼」，不是「拒絕了什麼」）

三條件全成立才建。否則直接在對話中拒絕即可。
